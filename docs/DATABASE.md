## Database

This project is using SQLModel and Alembic for database management.

### SQLModel

[SQLModel](https://sqlmodel.tiangolo.com/) is a library for interacting with SQL databases using Python.
It is built on top of SQLAlchemy and Pydantic, and it provides a simple and
intuitive way to define and manipulate database models.

Since SQLModel is built on top of SQLAlchemy, you can still use all the
features of SQLAlchemy, such as relationships, joins, transactions and 
execution calls such as (execute, exec is the SQLModels overloaded version of execute).
You might need to use execute instead of exec to run pure SQL queries.

We have defined the models in `app\db\models\`

As an example as how it looks you can see the `InterfaceGroup` model below:

```python
class InterfaceGroup(SQLModel, table=True):
    __tablename__ = "interface_group"
    id: int = Field(default=None, primary_key=True, index=True)
    name: str = Field(nullable=False)
    interfaces: List["InterfaceDb"] = Relationship(
        back_populates="interface_group"
    )
```
The `InterfaceGroup` model is a subclass of `SQLModel`, and it defines a
table in the database called `interface_group`. The `id` field is an
integer that is the primary key of the table, and it is automatically
generated by the database. The `name` field is a string that cannot be
null. The `interfaces` field is a list of `InterfaceDb` objects that
are children to the `InterfaceGroup` model. The `Relationship` function
is used to define the relationship between the two models.

#### Multiple models
There is a nice help functionality for having different models from the same 
element. Read more [here](https://sqlmodel.tiangolo.com/tutorial/fastapi/multiple-models/?h=multiple).

For example, if you have a model called `User`, you can create a
`UserCreate` model that only has the fields you need to create a user,
and a `UserPublic` model that has all the fields you need to send to the client.

### Alembic

Alembic is a lightweight database migration tool for use with SQLAlchemy. 
In other words, it is used to create the migration scripts that document the
evolution of the database schema over time.

#### How to use Alembic

*Important:* To run any of the commands below, you need to be in the `app` folder.

To run an "up" migration run:

    $ alembic upgrade head

To run a "down" migration, say to the previous migration runt.

    $ alembic downgrade -1

if you need to downgrade 2 versions change the value from -1 to -2.

To create a migration file run:

    $ alembic revision -m "Text describing the purpose of this migration"
